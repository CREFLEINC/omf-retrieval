# Development Workflow 트리거 평가

## Should trigger

### 명시적 요청

- `검색 API 구현을 시작해줘`
- `이 버그 원인을 조사하고 승인받은 수정까지 진행해줘`
- `설정 변경을 검증 Agent와 함께 처리해줘`

### 캐주얼 요청

- `이 테스트 좀 보완해줘`
- `README 내용 최신으로 좀 맞춰줘`
- `이 UI 배치, 컴포넌트로 정리해줄래?`

### 후속 수정

- `지난 계획의 작업 3만 다시 실행해줘`
- `이전 결과 기반으로 배포 스크립트를 개선해줘`
- `승인된 마이그레이션 작업을 계속해줘`
- `실패한 검증을 수정해서 재실행해줘`

## Should not trigger

### Near-miss 경계

- `방금 승인한 계획의 현재 상태만 알려줘`
- `이 메시지에 나온 TDD가 무슨 뜻인지 설명해줘`
- `계획을 승인할게`
- `이번 계획은 반려할게`
- `네 답변을 더 짧게 말해줘`
- `내가 붙여 넣은 코드 한 줄의 문법만 설명해줘`
- `작업을 중단해줘`
- `아직 어떤 파일도 보지 말고 선택지만 말해줘`
- `이전 보고서의 결론을 대화로 다시 읽어줘`
- `다음 승인 질문 하나만 해줘`
