# Development Workflow 드라이런

## 정상 흐름

1. 사용자가 기능 구현을 요청한다.
2. 오케스트레이터는 실행 없이 계획 보고서의 주제, 목적, 내용, 기대 결과와 검증
   방법을 제시한다.
3. 사용자가 범위를 명시적으로 승인한다.
4. 새 실행 Agent가 승인된 한 단위를 TDD로 구현하고 쉬운 무외부 의존 검증만 한다.
5. 다른 새 검증 Agent가 read-only 상태에서 계획된 모든 검증을 독립 실행한다.
6. 오케스트레이터가 두 보고서를 사용자에게 전달하고 다음 단위 진행 확인을 받는다.

## 오류 흐름

### 일반 검증 실패

1. 검증 Agent가 계획된 검증을 수행하고 검증 실패를 보고한다.
2. 조정 Agent는 발견 전체를 실행 Agent에 반환한다.
3. 실행 Agent는 승인 범위 안에서 발견을 모두 수정하고 증거를 갱신한다.
4. 동일한 검증 Agent 인스턴스가 계획된 전체 검증을 처음부터 재실행한다.
5. 계획 밖 수정이 필요하면 실행을 멈추고 재승인을 요청한다.

### 범위 변경

1. 실행 Agent가 RED 뒤 최소 구현 중 승인 계획에 없던 schema 변경 필요성을 발견한다.
2. 실행 Agent는 변경하지 않고 범위 변경, 영향과 대안을 보고한다.
3. 오케스트레이터는 수정 계획을 제시하고 재승인을 기다린다.
4. 재승인 전에는 이전 승인으로 schema 변경이나 관련 후속 작업을 실행하지 않는다.
5. 재승인되면 새 실행 Agent 인스턴스로 해당 단위를 수행한다.
6. 별도 검증 Agent가 원래 검증과 승인된 추가 검증을 모두 다시 실행한다.

### 검증 불가 변형

계획된 외부 환경이 준비되지 않으면 검증 Agent는 해당 항목을 `NOT RUN`으로 남기고
전체 판정을 `BLOCKED`로 보고한다. 실행 Agent의 쉬운 검증 통과로 대체하지 않는다.
