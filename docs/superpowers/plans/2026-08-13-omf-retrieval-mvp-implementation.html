문서 관계와 결론

정본과 열람본. 같은 경로의 2026-08-13-omf-retrieval-mvp-implementation.md가 1,500여 행의 실행 정본이다. 이 HTML은 프로젝트 관련자가 단계·책임·게이트를 빠르게 검토하기 위한 파생 열람본이다. 구현 시에는 Markdown의 파일 목록, 실패 테스트, 예상 결과와 검증 명령을 따른다.

구현은 18개 논리적 작업을 5개 승인 단계로 진행한다. 각 기능은 실패 테스트에서 시작하고, PostgreSQL 통합은 실제 pgvector 컨테이너에서, 최종 품질·성능은 지정 서버의 RTX 4090 GPU 0에서 검증한다. 단계 결과를 공유하고 사용자 확인을 받은 뒤 다음 단계로 이동한다.

작업 1의 assertion 기반 RED/GREEN

작업 1은 test 오류를 실패 근거로 사용하지 않는다. 각 RED에서 test collection과 필요한 import·metadata 조회는 성공하고, 아직 구현하지 않은 계약을 비교하는 assertion만 실패해야 한다. CLI의 최초 RED는 entry point 목록 assertion에서 멈추므로 load()를 실행하지 않는다.

완료 정의

완료는 코드 작성이 아니라 검증 증거다. 아래 조건이 전부 충족되고 사용자가 최종 승인해야 MVP 구현을 완료로 표시한다.

  • 승인된 REST·CLI·DB·검색·권한 계약 구현
  • unit·integration·contract test와 Domain·Application coverage 80% 이상
  • 실제 PostgreSQL 18 + pgvector 0.8.6 migration·검색·transaction 통과
  • OMF 고정 commit의 최초·증분·실패 격리·rollback E2E 통과
  • 승인된 30개 gold의 정량 기준과 100% gate 통과
  • RTX 4090 GPU 0의 p95·오류율·초기 색인 시간 통과
  • Gateway HTTPS, private bind, DB 비노출, source grant 선필터 확인
  • application image·DB image·model·source·config의 digest와 hash 기록
  • query·token·evidence 원문이 log·audit·image에 존재하지 않음
  • runbook·배포·장애 처리 문서와 검증 결과 인계

승인된 계획 사항

  1. 18개 작업과 5개 사용자 확인 지점
  2. /versions/만 historical로 보는 보수적 version 규칙
  3. 명시적 sidecar만 supersedes·potential conflict로 저장하는 규칙
  4. API token SHA-256과 질의 audit HMAC-SHA256의 분리
  5. audit_hmac_key secret file 추가
  6. 인증된 client만 readiness를 호출하는 정책
  7. 운영 전 model prepare CLI로 고정 revision을 cache하는 방식
  8. 단계 A부터 순차 구현하고 각 단계 결과를 확인받는 진행 방식
