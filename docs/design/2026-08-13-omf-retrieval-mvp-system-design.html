요약

이번 MVP는 생성형 답변 시스템이 아니라 검증 가능한 근거 검색 시스템이다. 사용자가 필요한 자료를 자연어로 요청하면, OMF 문서의 관련 절을 하이브리드 검색하고 직접 인용·파일 경로·제목 계층·행 범위·색인 커밋 SHA·내용 해시·문서 버전 및 결정 상태와 함께 전달한다. 검색 후 LLM 요약·분석은 2차 개발로 분리한다.

목표와 범위

사용자 가치

“어떤 자료가 필요한지 요청”하면 “거기에 맞는 자료를 찾아 근거와 함께 전달”한다.

MVP의 성공은 답변 문장이 자연스러운지가 아니라, 필요한 근거를 빠짐없이 찾고 그 근거를 원문에서 다시 확인할 수 있는지로 판단한다.

포함 범위

  • 자연어 검색 요청과 source·버전·경로·결정 상태 필터
  • 지정 Git commit의 정리된 Markdown 문서 색인
  • 제목 계층 기반 Parent–Child 분할과 콘텐츠 기반 재사용
  • 키워드·벡터 검색 및 RRF 결합
  • 원문 근거 패키지와 충돌·중복·버전 정보 반환
  • REST API, API를 호출하는 Search CLI, 운영자 전용 Admin CLI
  • 인증·source 권한·감사 이벤트·최소 헬스체크와 구조화 로그
  • 검색 품질·성능 평가와 원자적 색인 전환·직전 성공본 롤백

2차 개발 범위

  • Codex API 또는 내부 Kanana 모델을 이용한 요약·분석·답변 생성
  • 대화형 Agent, MCP, function tool 및 후속 질의
  • 기존 CrefleAI GPU 모델 서버 연동
  • TEI 분리, 리랭커, ANN 인덱스, ParadeDB·Korean Lindera
  • 자동 백업·외부 복제·복원 훈련·RPO/RTO
  • Prometheus, Grafana, 중앙 로그 수집과 알림
  • Git 전체 이력 검색과 완전한 의미 기반 충돌 판정

MVP 운영 한계. PostgreSQL 영속 볼륨은 사용하지만 자동 백업은 제공하지 않는다. DB 장애 시 원본 Git commit으로 색인을 재생성할 수 있으나 API 클라이언트, 감사 로그와 실행 이력은 소실될 수 있다. 사용자 확대 또는 정식 운영 전에 2차 백업·복구 개발을 완료해야 한다.

정본·버전·충돌 규칙

  1. 전체 문서와 명시적 버전 스냅샷을 색인하되 일반 검색은 현재본을 우선한다.
  2. 사용자가 이전 버전·변경 전·최초 결정을 요구하면 과거본을 검색한다.
  3. 완전히 같은 내용은 콘텐츠 해시로 감지하고 실제 내용·chunk·embedding은 재사용하되 모든 원본 경로를 보존한다.
  4. 화면 구성·IA·프로그램 배치 정책은 uiux, 업무 흐름·요구사항·데이터 모델은 docs의 소유권을 따른다.
  5. 확정기록, 결정서, [확정] 표기는 일반 조사 문서보다 우선한다.
  6. 같은 지위에서는 버전과 결정일을 비교하며, 남은 충돌은 양쪽 근거를 함께 공개한다.
  7. MVP는 의미적 충돌을 LLM으로 추론하지 않는다. 원문이나 관리 설정에서 명시적으로 확인된 관계만 potential_conflict로 표시한다.

응답: 동일 근거 1개 + 원본 경로 2개

파일 경로는 출처 좌표이고 콘텐츠의 정체성은 SHA-256 해시다. 같은 경로의 내용이 새 commit에서 바뀌면 새 해시가 생기며, 같은 내용이 여러 경로에 있으면 검색 산출물은 한 번만 만들고 모든 경로를 인용 정보로 보존한다.

초기 벡터는 1024차원이지만 모델 교체 가능성을 유지하기 위해 차원을 고정하지 않은 PostgreSQL vector 컬럼을 사용한다. 검색 시 활성 index config의 모델과 차원이 모든 query·document vector에 동일한지 검증하며, 모델 또는 차원이 바뀌면 별도 embedding 설정으로 재색인한다.

임베딩 정책

  • 모델: Qwen/Qwen3-Embedding-0.6B, 초기 출력 1024차원
  • 구현: 같은 Python 이미지 안의 Sentence Transformers 기반 EmbeddingProvider
  • 운영: GPU 0을 필수 사용하고 CUDA가 보이지 않으면 readiness 실패
  • API: 프로세스당 모델을 한 번 로딩하므로 초기 worker는 1개
  • Admin CLI: 같은 provider로 문서 embedding을 생성
  • 모델명·revision·차원·instruction·라이브러리 버전을 설정과 색인 실행에 기록
  • OMF 평가가 기준 미달일 때만 BAAI/bge-m3와 비교
  • Kanana Instruct는 임베딩에 사용하지 않음

                                ▼ 단일 DB 트랜잭션

B 문제 시: Admin CLI로 active 포인터를 A로 롤백
  • 현재 활성본과 직전 성공본의 검색 데이터를 보존한다.
  • 더 오래된 실행은 commit SHA·설정 hash·통계만 보존하고 검색 데이터는 정리한다.
  • 실패 실행은 실패 원인과 통계만 남기고 미완성 데이터를 정리한다.
  • 같은 source profile의 동시 색인은 PostgreSQL advisory lock으로 막는다.
  • RRF 값만 바뀌면 재색인하지 않고, 청킹 설정 변경은 재파싱하며, 모델·차원 변경은 embedding을 다시 만든다.

검색 처리

하이브리드 검색 기본값

  • 키워드와 벡터 검색을 독립적으로 실행하여 각각 상위 50개 child를 선택한다.
  • RRF 상수 k=60, 키워드 가중치 1.0, 벡터 가중치 1.0으로 시작한다.
  • 결합 점수는 각 검색기의 순위 r에 대해 weight / (60 + r)를 합산한다.
  • 벡터는 초기 코퍼스가 작으므로 ANN 없이 cosine 정확 검색한다.
  • 같은 parent의 여러 child는 전달 화면에서 묶되 원본 child와 개별 행 범위·점수를 보존한다.
  • 긴 절 편향을 막기 위해 evidence item은 포함된 child 중 최고 RRF로 순위를 정하고 추가 match는 가산하지 않는다.
  • 초기 RRF 값은 골드셋 결과로 조정할 수 있으나 품질 기준을 낮추지 않는다.

보안과 접근 제어

네트워크 신뢰 경계

  • 중앙 Nginx Gateway가 crefle.com TLS 인증서와 호스트명 reverse proxy를 담당한다.
  • FastAPI 포트는 검색 서버의 사설 IP에만 bind하고 방화벽에서 Gateway IP만 허용한다.
  • Gateway가 X-Forwarded-For, X-Forwarded-Proto=https, Host, X-Request-ID를 재설정한다.
  • FastAPI는 지정된 Gateway에서 전달된 프록시 헤더만 신뢰한다.
  • PostgreSQL은 Compose 내부망에만 존재하며 호스트 포트를 공개하지 않는다.

API 토큰과 권한

  • 클라이언트별로 key ID와 256-bit 이상의 무작위 secret을 발급한다.
  • DB에는 key ID, token hash, 상태, 선택적 만료일만 저장하며 원문은 발급 시 한 번만 표시한다.
  • 회전 시 새 토큰과 기존 토큰을 잠시 함께 활성화한 뒤 기존 토큰을 폐기한다.
  • API 토큰에는 검색 권한만 부여하고 Admin 권한은 제공하지 않는다.
  • Admin 작업은 SSH로 접속한 phoebe-deploy 운영자가 CLI로 수행한다.
  • source 권한 조건은 후보 검색 전에 적용하여 존재 여부와 점수도 노출하지 않는다.

비밀정보와 데이터 취급

  • DB 비밀번호는 /opt/omf-retrieval/secrets/postgres_password의 권한 600 파일로 관리한다.
  • Git, Docker image, Compose 환경변수와 로그에 secret을 기록하지 않는다.
  • Registry 인증은 서버의 Docker credential store가 담당한다.
  • 원문과 색인은 사내 환경에만 저장하고 docs/raw 등 제외 자료를 외부로 전송하지 않는다.
  • MVP에는 LLM 생성 호출이 없으므로 원문이 Codex API나 CrefleAI로 전송되지 않는다.
